## Rejected approaches
- **Google Photorealistic 3D Tiles / CesiumJS**: realistic mesh (violates the user's keep-low-poly decision), requires a Google Cloud billing account + API key, heavy on load, and its terms forbid extracting the mesh into a game model.
  **Why rejected**: conflicts with user decisions and needs credentials the build cannot assume.
- **Live OSM tile fetch at runtime**: map would depend on network tiles at open and blow the data budget for a full Shenzhen–Huizhou extent.
  **Why rejected**: the miniature's road network and coastlines are baked in as low-poly geometry at build time, following the real corridor layout (深南大道/滨海大道/北环大道 east–west, 广深/沿江/机荷 corridors, 惠深沿海高速 up the coast to 惠州, Daya Bay / Shuangyue Bay coastline) — same visual result, zero runtime dependency.
- **One artifact with adaptive quality tiers**: the user explicitly chose two independent versions.
  **Why rejected**: user instruction.

Imagery not needed: the world is a real-time low-poly 3D scene (Three.js geometry, vertex colors, baked lighting) — there are no photographic subjects; furniture and locations are 3D models in-scene, matching the user's keep-low-poly decision.

## White-screen hardening (2026-11-06, user: Mac App 里打开全白、等很久也不加载)
- Diagnosis from the captured evidence bundle: the fresh render capture is clean (setup screen, no console errors), so the failure lives in state only the user's device has — a local save written by an older build and/or the Mac app webview refusing WebGL. Three unguarded paths could each turn that into a permanent full-white panel: the restore effect backfilled only some GameState fields while render helpers (`gs.furniture.filter`, comfort/badges) read others raw; `THREE.WebGLRenderer` was constructed unguarded in MapView and LifeStage; and the app had no error boundary and no boot fallback, so any startup throw unmounted everything with no recovery.
- Fixes shipped: (1) `sanitizeSave` in App.tsx re-validates and coerces every restored field (arrays filtered to strings, numbers finite-checked with identity/city-based defaults, day/career clamped, identity re-resolved) and discards an unusable save back to the setup screen; NPC-wall generation moved into its own try/catch. (2) `RootErrorBoundary` in main.tsx catches any render/effect crash and offers 重新打开 / 清除本地存档并重新开始 (server multiplayer data untouched). (3) MapView and LifeStage catch a refused WebGL context and degrade — MapView to a clickable location list, LifeStage to the emoji actor — instead of crashing. (4) index.html gained a 9s boot watchdog: if the root is still empty it renders reload / clear-save recovery UI inline.
- Live probe verification: entered the city as a fresh player (full game UI + 3D map, no console errors), then reloaded — the save restored straight back into the game view (day 1, ¥1,800, join feed intact), which is exactly the open-with-existing-save path that white-screened for the user. The corrupt-save and WebGL-refusal branches could not be injected through the probe (no script-eval op); they are covered by source review plus the boundary layering.

## Rail trips between non-station places (2026-11-06, user screenshot: 大梅沙→海边公园被「没有轨道线路相连，已取消出行」)
- Diagnosis (reproduced offline against the real data): the transfer planner was never broken — 大梅沙→华强北 routes fine (8号线→2号线， 10 stops, transfer 仙湖路）. The failure was endpoint anchoring: `findMetroRoute` can only start/end at a location that is itself a station's locId, and 22 of 42 Shenzhen locations (44 of 68 across both cities) have no station — 海边公园（深圳湾公园 `fun`) among them, while 大梅沙 itself IS the 8号线 terminus. ## Currency display fix (2026-11-07, user: 港币标价没落地）
The HK build promised 港币标价 on the city card, but the setup screen,
HUD and cross-city controls still rendered every amount with ¥. Fixed by
making the display currency follow the city the player is standing in:
- `curSym` / `fmtMoney` / `crossFareLabel` in data.ts are the single
  source: hk → `HK$`, sz/hz → `¥`. App.tsx's in-component `fmt` shadows
  the module default and resolves from the live `gs.cityKey` (falling
  back to the setup screen's picked city), so identity money/pay on the
  setup screen, balance/goal/rent, wages, food, lodging, ZhuyaHome
  prices, transport fares, sign-in and quiz rewards all render in the
  current city's currency. Leaderboard rows use each player's OWN city
  currency. Random-event copy (authored with ¥ in events.ts) is
  re-denominated at render time via `locText` when the player is in HK.
- Cross-border HSR fares are labelled in the DEPARTURE city's currency
  everywhere they appear (top-bar and map-edge switch buttons, the
  crossing log line and arrival toast, the port 「过关去…过日子」
  actions): West Kowloon departures read `HK$75（西九龙出发 · 港币）`,
  Shenzhen departures `¥75（深圳出发 · 人民币）`, Huizhou departures
  `¥120（惠州出发 · 人民币）`. The domestic Shenzhen⇄Huizhou fare stays
  a plain ¥40. The server's finishSeason feed line also uses HK$ for
  Hong Kong players.
- Guide-card prices in experience.ts were already real per-city prices
  (SZ/HZ in ¥, HK in HK$) and were left untouched.
