# 深惠人生：走向全中国、全世界的架构方案

> 状态：方案稿（2026-11-07）。不改代码，只回答「用户、聊天、家、公司、租房、交通怎么统一维护，怎么接入全中国、全世界，在哪些平台上架」。

## 0. 现在是什么样

| 方面 | 现状 | 上规模的问题 |
|---|---|---|
| 身份 | 浏览器里随机生成 `playerId`，存在 localStorage；换设备靠「云存档码」 | 没有账号，清缓存就丢；无法实名、无法封号、无法跨设备自然同步 |
| 存档 | **客户端说了算**：钱、职级、家具都在本地算，服务器只收快照 | 能被改数据作弊；排行榜、组局、交易都没法信 |
| 服务器 | 单机 Node + SQLite，客户端每 4–6 秒轮询 | 撑不住大量同时在线；没有实时推送 |
| 世界 | 两座城（深圳、惠州），地点、地铁、天气是写死 + OSM 生成的数据 | 加城市要手工跑脚本 |
| 时间 | 已改成北京时间：游戏日 = 真实日期，行动有真实冷却，地铁/商场按真实营业时间 | 换到别的国家要换成当地时区 |
| 聊天 | 城市公开频道 + 任意私聊（拉黑、举报、过滤、限频） | 没有翻译；审核靠关键词 |

## 1. 目标架构（一张图说清）

```
 客户端（Web / Steam / App 用同一套 React + Three.js；微信小游戏没有 DOM，界面层要另做）
        │  HTTPS（读多写少的接口）      WebSocket（在线、位置、聊天、组局）
        ▼                                ▼
   API 网关 ──── 认证（账号 / 实名 / 防沉迷）
        │
 ┌──────┼──────────────┬──────────────┬───────────────┐
 游戏逻辑服务        社交服务        世界数据服务       内容安全
 （服务端权威：       （好友、私聊、    （城市、地点、     （过滤、分类模型、
  钱、行动、冷却、     组局、搭子、     交通、营业时间、    举报队列、人工审核）
  房子、工作、车）     翻译）          天气、时区）
        │                │               │
   Postgres（按区域部署）  Redis（在线、频道、限流）  对象存储 + CDN（模型、照片、地图瓦片）
```

### 1.1 用户系统
- **账号**：手机号/邮箱验证码，第三方登录（Apple、Google；国内用微信）。一个账号 = 一个全局 `user_id`；现在的匿名 `playerId` 首次登录时绑定迁移过来，存档不丢。
- **角色**：一个账号可以在不同城市/赛季有不同的「人生」（`life`），保留跨局的深漂档案、图鉴、成就。
- **国内必须**：实名认证 + 未成年人防沉迷（限时段、限时长、限充值）。
- **公开 ID**：继续用现在的「公开 id ≠ 私有 id」设计，任何客户端都拿不到别人的私有 id。

### 1.2 服务端权威的游戏状态
把现在本地的 `GameState` 搬到服务器，客户端只发「我想做什么」（意图），服务器校验后返回结果：

| 表 | 说明 |
|---|---|
| `users` / `lives` | 账号；每一局人生（城市、身份、赛季、开始日期） |
| `ledger` | **钱只记流水**（工资、房租、消费、红包），余额由流水算出——防作弊、可对账 |
| `homes` / `leases` | 房子是真实地点上的「房源」：租约（月租、押金、起止日期）、买房（首付、月供）、合租 / 同居 |
| `jobs` / `companies` | 雇佣关系、职级、工资单；公司可以是虚构品牌 + 真实写字楼地址 |
| `vehicles` / `licenses` | 驾照、车辆（租 / 买）、违章 |
| `inventory` / `collections` | 鱼、娃娃、签文、照片…… |
| `relations` | 好友、拉黑、搭子次数、NPC 好感 / 恋爱 |
| `messages` / `parties` | 私聊、组局（已有，迁到 Postgres） |
| `cooldowns` | 每个行动的真实冷却，服务器计时 |

### 1.3 实时
- WebSocket 网关按「城市频道」分组推送：谁在线、谁在哪、聊天、组局状态。Redis pub/sub 做多台服务器之间的广播。
- 地图上的人物位置每几秒推一次（不是每帧），客户端插值。

## 2. 接入全中国、全世界的真实数据

| 数据 | 来源 | 注意 |
|---|---|---|
| 地点（景点、商场、医院、派出所…） | OpenStreetMap；国内可补高德/百度 POI（需商用授权） | OSM 是 ODbL：要署名，衍生数据库要同样开放 |
| 楼宇高度 / 轮廓 | OSM buildings（已用来生成天际线）；国内覆盖不全的城市可用卫星影像估算 | 地图比例尺下只画天际线，地标手工建模 |
| 道路 | OSM 路网 | 小地图上做简化 |
| **交通** | 全球公交/地铁：GTFS（Mobility Database、Transitland）；国内地铁线网用开放资料 + 人工校对；高铁/航班用公开时刻表的近似 | 每座城的运营时间、票价规则不同，存在「交通方式表」里，代码不写死 |
| 营业时间 | OSM `opening_hours`，没有的按类别给默认值（现在已这样做） | |
| 天气 | 现在的实时天气接口，按城市坐标查 | |
| 时区 | 每座城市带 IANA 时区；**游戏时间 = 所在城市的当地时间** | 跨时区组局时显示双方当地时间 |

城市上线流程做成一条流水线：`选城市 → 拉 OSM/GTFS → 生成地点/线网/天际线 → 人工挑地标做模型 → 翻译地名 → 上线`。现在 `tools/` 里深圳、惠州的脚本就是这条流水线的雏形。

## 3. 不同国家的人怎么沟通

- 每条消息存「原文 + 检测到的语言」。
- 读的人如果语言不同，**按需翻译**（大模型翻译，结果按「消息 × 目标语言」缓存），界面上可以切换看原文。
- 审核在**原文**上做，翻译后的文本也过一遍过滤。
- 私聊：现在是「任何人都能私聊」，上规模后建议加：新账号 24 小时内只能私聊好友/组过局的人、陌生人第一条消息要对方同意、对未成年人默认只开放好友私聊。

## 4. 「信息统一」的边界：合规分区

**全球一个大服，在中国不可行，这一点要先想清楚：**

- **中国大陆**：ICP 备案；网络游戏上线运营需要**版号**（尤其是有付费）；实名 + 防沉迷；《个人信息保护法》要求境内用户的个人信息**存储在境内**，出境要做安全评估或签标准合同；公开聊天要有内容审核。
- **海外**：GDPR（欧盟）、CCPA（加州）、COPPA（13 岁以下）；应用商店要求有 UGC 的应用必须有过滤、举报、拉黑（我们已经有）。

**建议**：两个区域部署——「中国区」（数据在境内）和「国际区」。游戏内容、城市数据、代码是同一套；账号和个人数据分开。中国区和国际区之间的跨区聊天，上线初期不做；以后如果要做，需要先过一遍法务评估。

## 5. 上架平台：建议顺序

| 平台 | 适合 | 门槛 | 建议 |
|---|---|---|---|
| **独立网页** | 迭代最快；PC、手机浏览器都能玩；分享链接即玩；海外最容易 | 国内要 ICP 备案；付费要版号 | **现在就是**，继续作为主阵地和测试服 |
| **微信小游戏** | 国内最强的社交裂变：群分享、好友关系链、「好友正在玩」 | 需要软著；**涉及付费一般需要版号**（以微信官方最新规则为准）；**小游戏运行环境没有网页 DOM**：现在的 React 界面不能直接跑，要把界面改成画在 Canvas 上（3D 地图部分的 Three.js 可以保留）；另一条路是「小程序 + web-view 内嵌网页」，但需要企业主体和备案域名；主包体积有限制，模型和照片要走 CDN | **国内第一站**，但要先评估界面改造量；在那之前用网页链接在微信里分享 |
| **Steam** | 海外 PC 玩家；「真实城市生活模拟」题材合适；创意工坊可以让玩家做城市 | 打包成桌面应用（Tauri/Electron）；商店页、成就；国际区服务器 | **海外第一站**：抢先体验（Early Access） |
| iOS / Android App | 留存和推送最好 | 国内安卓商店和 iOS 国区都要版号；海外正常上架 | 第三阶段，用 Capacitor 套同一套前端 |

一句话：**网页做主阵地 → 国内上微信小游戏（先免费）→ 海外上 Steam → 最后做原生 App。** 网页、Steam、App 是一套代码，区别在登录、支付和打包；微信小游戏要单独做一层界面。

## 6. 分阶段路线

1. **账号与服务端权威（1–2 个月）**：登录；匿名存档迁移；钱改成流水；行动校验和冷却放到服务器；SQLite 换 Postgres。
2. **实时与社交（1 个月）**：WebSocket；好友；消息翻译；审核后台。
3. **城市流水线（持续）**：每加一座城跑一遍流水线；先做大湾区（广州、东莞、珠海、香港、澳门），再做北上杭，再做海外城市。
4. **平台**：微信小游戏适配（登录、分享、包体）；Steam 打包；国际区部署。
5. **合规**：软著、ICP、版号申请；隐私政策按地区拆分；未成年人模式。
